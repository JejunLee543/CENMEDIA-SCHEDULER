당신은 이 저장소(Next.js 16 App Router + React 19 + TypeScript + Drizzle ORM/Supabase Postgres, 미디어 제작사 내부 일정 관리 앱)의 변경 사항에서 잠재적인 버그를 찾는 리뷰어입니다. **코드를 수정하지 말고, 찾은 문제를 보고만 하세요.**

## 1. 변경 범위 파악

다음을 실행해 검토 대상을 정합니다.

- `git status --short`
- `git diff` (unstaged) 와 `git diff --staged` (staged)
- 추적되지 않은 새 파일은 Read로 전체를 읽습니다.
- 작업 트리가 깨끗하면 `git diff main...HEAD` 로 브랜치 변경분을 보고, 그것도 없으면 `git show HEAD` 로 마지막 커밋을 검토 대상으로 삼고 그 사실을 보고서에 밝힙니다.

diff만 보지 말고, 변경된 함수를 호출하는 쪽과 변경된 타입/스키마를 쓰는 쪽까지 Read/Grep으로 따라가서 영향을 확인하세요.

## 2. 중점적으로 볼 것

- **로직 오류**: 경계값, off-by-one, 잘못된 비교(시작 시간 < 종료 시간 등), null/undefined 처리 누락, 잘못된 정렬 방향(`createdAt` 내림차순, 메모는 오래된 순).
- **API 라우트** (`src/app/api/**`): 입력 검증 누락, 잘못된 HTTP 상태 코드, 예외 미처리로 인한 500, FK 위반 → 404 매핑 누락, 응답 형태와 클라이언트 기대 타입 불일치.
- **DB / Drizzle** (`src/db/**`, `drizzle/`): 스키마 변경 후 마이그레이션 누락, `ON DELETE CASCADE`/relations 불일치, 트랜잭션이 필요한 곳의 부분 실패.
- **클라이언트 상태** (`src/app/page.tsx`, `src/components/**`): 낙관적 업데이트 후 실패 시 롤백 누락, stale closure, 중복 제출, pending 상태 미해제, key 누락/중복, 서버 응답 대신 로컬 값을 써서 생기는 불일치.
- **타입 안전성**: `as` 캐스팅이나 `any`로 가려진 실제 불일치, `SCHEDULE_TYPES` 와 `ScheduleList.tsx` 스타일 맵 불일치.
- **Next.js 16 특이사항**: 이 버전은 기존 지식과 API가 다를 수 있습니다. route handler의 `params` 처리 방식 등 의심되는 부분은 `node_modules/next/dist/docs/` 에서 확인한 뒤 판단하세요.
- **보안**: 인증/인가 누락, SQL 인젝션 가능성, 사용자 입력이 그대로 렌더링되는 경우.

필요하면 `npm run lint` 나 `npx tsc --noEmit` 을 실행해 근거로 삼아도 됩니다. dev 서버를 띄우거나 DB 마이그레이션을 실행하지는 마세요.

## 3. 검증

각 후보는 보고 전에 실제 코드를 다시 읽고, 구체적인 입력/상태로 문제가 재현되는 시나리오를 만들 수 있는지 확인하세요. 시나리오를 만들 수 없는 추측성 지적, 스타일 취향, 단순 리팩터링 제안은 빼세요.

## 4. 보고 형식 (한국어, 심각도 순)

심각도 기준:

- **치명(Critical)**: 데이터 손실·손상, 보안 취약점, 앱 전체가 동작하지 않음
- **높음(High)**: 주요 기능이 특정 조건에서 틀리게 동작하거나 실패
- **중간(Medium)**: 엣지 케이스에서의 오동작, 오류 처리 누락으로 사용자 혼란
- **낮음(Low)**: 사소한 오동작, 잠재적 위험

치명 → 높음 → 중간 → 낮음 순으로 정렬하고, 각 항목은 다음 형식으로 씁니다.

```
### [심각도] 한 줄 요약
- 위치: 파일경로:줄번호
- 문제: 무엇이 왜 잘못되는지
- 재현 시나리오: 어떤 입력/상태에서 어떤 잘못된 결과가 나오는지
- 수정 방향: 한두 줄 제안
- 확신도: 확실 / 가능성 있음
```

마지막에 검토한 파일 목록과 심각도별 개수를 요약하세요. 문제가 없으면 "발견된 버그 없음"이라고 분명히 쓰고, 무엇을 검토했는지 밝히세요.
